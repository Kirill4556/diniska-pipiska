# ТЗ: приложение-сплиттер mp3 → минус + вокал

*14.11.2026 · черновик v1*

## 1. Цель и допущения

Приложение принимает mp3-файл песни и отдаёт **два файла**:

1. **Минус** — инструментал без голоса.
2. **Вокал** — «чистый голос» без музыки.

**Допущение:** «чисто текст» понято как вокальная дорожка (голос, который поёт текст). Кроме того, делается текстовый файл со словами песни (вариант А, входит в версию 1).

Приложение делается как отдельный модуль: работает само по себе и может стать этапом подготовки треков для караоке-приложения.

## 3. Функциональные требования

- **FR-1.** Вход: один mp3 (перетаскиванием, кнопкой или аргументом CLI). Желательно также wav, flac, m4a.
- **FR-2.** Выход: два файла в выбранной папке: `<имя>_instrumental` и `<имя>_vocals`.
- **FR-3.** Формат выхода выбирается: mp3 (битрейт 192/256/320 кбит/с), wav или flac. По умолчанию mp3 320.
- **FR-4.** Выбор модели: «быстро» и «качественно» (разные модели, см. раздел 5).
- **FR-5.** Прогресс-бар и возможность отмены.
- **FR-6.** Пакетная обработка: несколько файлов или папка целиком, очередь.
- **FR-7.** Автоопределение GPU (CUDA); при его отсутствии работа на CPU с предупреждением о времени.
- **FR-8.** Модели скачиваются при первом запуске и кэшируются локально; дальше приложение работает офлайн.
- **FR-9.** Сохранение тегов (название, исполнитель, обложка) в выходных файлах.
- **FR-10.** Понятные сообщения об ошибках: нет ffmpeg, битый файл, нет места на диске.

**Входят в версию 1 (варианты А, Б, В, З):**

- **FR-11 (А).** Текст песни: распознавание по вокальной дорожке, вывод `.txt` и `.lrc` с таймкодами; язык RU/EN определяется автоматически или задаётся вручную; текст можно поправить перед сохранением.
- **FR-12 (Б).** Режим 4 стемов: вокал, барабаны, бас, остальное; галочками выбирается, что смешать в минус.
- **FR-13 (В).** Бэк-вокал отдельно: основной голос, бэк-вокал и минус (с бэк-вокалом и без него) сохраняются отдельными файлами.
- **FR-14 (З).** Вход по ссылке на видео или трек: файл скачивается и обрабатывается как обычный mp3; перед загрузкой показывается напоминание об авторских правах.

## 4. Нефункциональные требования

- Платформы: Linux и Windows.
- Вся обработка локально, файлы никуда не отправляются.
- Скорость: трек 3–4 минуты на GPU — не дольше 1 минуты, на CPU — не дольше 10 минут (ориентир, уточнить на вашем железе).
- Память: не падать на длинных треках (обработка кусками, параметр segment).
- Лицензии: движок и модели проверить на допустимость использования; при форке Nightingale учитывать GPL-3.0.
- Зависимость: ffmpeg (в Windows поставляется вместе с приложением).

## 5. Технические решения

- **Язык ядра:** Python 3.10+ (вся экосистема разделения звука там).
- **Движок:** `audio-separator` с режимом двух стемов (instrumental + vocals); Demucs `htdemucs` / `htdemucs_ft` как альтернатива.
- **Модели:** быстрый режим — Demucs htdemucs; качественный — модели Roformer/MDX из списка `audio-separator --list_models` (в списке проекта для лучших вокальных моделей указан SDR около 12.9).
- **Интерфейс, MVP:** CLI, затем окно на PySide6 (Qt) — один код для Linux и Windows. Альтернатива: веб-интерфейс на Gradio для быстрого прототипа.
- **Упаковка:** PyInstaller или `uv tool` для Linux; установщик для Windows.

## 6. CLI-интерфейс (MVP)

```
splitter song.mp3 --out ./result --format mp3 --bitrate 320 --quality high
splitter ./album --batch --out ./result
```

Результат: `result/song_instrumental.mp3` и `result/song_vocals.mp3`.

## 7. Этапы работы

1. **Прототип (1 день):** скрипт на audio-separator, проверка на 5–10 разных песнях (русские, английские, плотная аранжировка).
2. **CLI (1–2 дня):** параметры, форматы, пакетный режим, теги.
3. **GUI (3–5 дней):** окно, очередь, прогресс, настройки.
4. **Упаковка (2–3 дня):** сборка для Linux и Windows, проверка на чистой машине.
5. **Интеграция** в караоке-приложение (по желанию).

Между этапами 3 и 4 добавляется этап **«Расширения» (4–6 дней):** распознавание текста (А), режим 4 стемов (Б), бэк-вокал (В), загрузка по ссылке (З).

## 8. Критерии приёмки

- Из mp3 получается ровно два файла, их длина совпадает с оригиналом (отклонение до 50 мс).
- Сумма минуса и вокала по звучанию близка к оригиналу, в минусе слышны остатки голоса не громче, чем у UVR с той же моделью.
- Работа без интернета после первой загрузки моделей.
- Пакет из 20 треков обрабатывается без падений.
- Запуск на Linux и Windows без ручной установки зависимостей.

* Для песни создаётся `.lrc` с таймкодами, в режиме 4 стемов получается четыре файла, в режиме бэк-вокала есть отдельный файл бэк-вокала.
* Ссылка на трек скачивается и обрабатывается без ручных шагов.

## 9. Варианты доработки

Варианты **А, Б, В и З включены в версию 1** (требования FR-11…FR-14); Г, Д, Е и Ж остаются на потом.

**А. Текст песни (файл со словами).** Распознавание речи из вокальной дорожки (Whisper и аналоги; важно, что распознавать удобнее по уже выделенному вокалу, а не по всей песне) плюс подбор готовых текстов по названию. Выход: `.txt` или `.lrc` с таймкодами. Для русских песен потребуется проверка качества и ручная правка.

**Б. Дополнительные дорожки.** Разделение на 4 стема: вокал, ударные, бас, остальное. Позволяет делать минус без баса или без ударных для репетиций.

**В. Бэк-вокал отдельно.** Отделить основной голос от бэк-вокала (в UVR есть модели «Karaoke»), чтобы в минусе можно было оставить подпевки.

**Г. Очистка вокала.** Убирать эхо и реверберацию, шумы (модели de-reverb / de-noise из экосистемы UVR).

**Д. Регулировка тональности и темпа.** Сдвиг тональности под свой голос и изменение темпа без смены высоты.

**Е. Интеграция с караоке-приложением.** Автоматическая подготовка трека при добавлении в библиотеку, кэш результатов, передача минуса в плеер, а вокала для сравнения высоты тона при оценке пения.

**Ж. Веб-сервис или API.** Обёртка на FastAPI и очередь задач; подходит, если нужно обрабатывать треки на отдельном сервере с GPU (ваш стек Go/Next.js может вызывать его по HTTP).

**З. Скачивание по ссылке.** Приём ссылки на видео или трек вместо файла (с проверкой прав на использование).

## 10. Риски

- Качество разделения зависит от песни: на плотной аранжировке в минусе остаются «призраки» голоса.
- Без GPU обработка заметно медленнее.
- Авторские права: инструмент для личного использования; публикация полученных минусов — на ответственности пользователя.
- Размер: модели и зависимости (PyTorch) делают установщик тяжёлым (порядка гигабайта).
